# 선박 2축 수평유지 시뮬레이터

실제 연구선의 Roll·Pitch 관측 기록을 입력으로 사용해 2축 짐벌 상판을 제어합니다. Optuna의 TPE가 여러 PID 조합을 반복 평가합니다. 별도의 검증 구간에서 제어 OFF, 수동 PID, 최적화 PID의 3D 자세와 성능을 비교할 수 있습니다.

## 실행

ZIP을 풀고 `app.py`가 있는 폴더에서 실행합니다. Python 3.11이 필요합니다.

**Windows PowerShell**

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

**macOS / Linux**

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

터미널에 표시된 로컬 주소를 브라우저에서 엽니다. 번들된 자료를 사용하는 데는 별도 계정이나 데이터 다운로드가 필요 없습니다.

## 캡스톤 시연 순서

1. 사이드바에서 **R/V Gunnerus · 실측**을 선택합니다. 기본 실험 A, B, C는 서로 겹치지 않는 실측 구간입니다.
2. **3D 시뮬레이션**에서 수동 PID를 재생합니다. 상판의 실선과 제어 OFF의 주황색 윤곽을 비교하거나 카메라를 **수평유지장치 확대**로 바꿉니다.
3. **PID 설정**에서 수동 이득, 모터와 모의 IMU를 확인합니다. 현재 설정을 JSON으로 내려받아 다시 적용할 수 있습니다.
4. **AI 자동 최적화**에서 3변수 또는 6변수, 탐색 범위, 실험 횟수를 정하고 시작합니다. 진행률과 누적 최저 점수를 확인합니다.
5. 학습에 사용하지 않은 B, C 구간의 결과를 확인하고 **최적 PID 적용**을 누릅니다. 적용된 이득은 3D 시뮬레이션과 성능 분석에 반영됩니다.
6. **성능 분석**에서 B 구간을 선택해 세 조건의 RMS, 최대 오차, ±1° 이내 비율, 모터 사용량을 비교합니다. 원본 시각·모터·PID 시계열은 CSV, 모델 설정·데이터 출처·성능 지표는 JSON으로 다운로드합니다.
7. 다른 선박에서 확인하려면 사이드바 C 구간의 입력을 **R/V Akademik Tryoshnikov · 실측**으로 바꾸고 각 축의 양의 방향을 지정합니다. 부호 선택은 결과에 기록됩니다.

3D에서 **일시정지**는 현재 계산 스텝을 고정합니다. **정지**는 관절, 지연 큐, PID 적분 등의 초기 상태인 0초로 돌아갑니다. **처음부터 재생**은 0초부터 재생을 시작합니다. **한 스텝**은 일시정지 중 제어 주기 한 번만 진행합니다. 시간 이동은 시작점부터 계산한 상태에서 가장 가까운 스텝을 선택합니다. 데이터 끝에서 자동으로 멈춥니다.

## 선박 정보 및 제원

사이드바에서 운동 데이터 출처를 선택하면 **선박 정보 및 제원**에 해당 선박의 제원과 출처를 표시합니다. 검증 C에 다른 선박 기록을 고르면 C의 3D 장면에도 그 선박의 제원이 적용됩니다.

| 선박 | 종류 | 전장 | 선폭 | 흘수 | 배수량 |
| --- | --- | ---: | --- | --- | --- |
| R/V Gunnerus | 다목적 연구선 | 36.25 m | 형폭 9.60 m | 형흘수 2.70 m | 543.79 t (2023 파도 차폐 실험 제원) |
| R/V Akademik Tryoshnikov | 극지 연구선 | 133.53 m | 최대 선폭 23.25 m | 설계 수선 흘수 8.50 m | 16,539 t |

Gunnerus의 길이·형폭·흘수는 [NTNU 선박 제원](https://www.ntnu.edu/documents/1262202806/0/Specifications%2BRV%2BGUNNERUS%2B20260305.pdf/8430b710-1719-2cfe-2bce-a4f4d9253252?t=1772726476143), 배수량은 [2023 실험을 정리한 공개 자료의 논문 표 2](https://github.com/shiplab/gunnerus/tree/main/operational/wave-shielding-2023#the-case-in-gunnerus-terms)를 사용합니다. Tryoshnikov는 [운항기관 AARI](https://www.aari.ru/the-fleet/rv-%C2%ABakademik-tryoshnikov%C2%BB)의 제원을 사용하고, 개략 갑판 높이는 [러시아 선급](https://rs-class.org/c/getves.php?imo=9548536)의 등록 선체 깊이를 참고합니다.

업로드 파일을 선택하면 이름, 선종, 길이, 폭, 흘수와 선택적인 수면 위 높이를 입력할 수 있습니다. 수면 위 높이는 상부 구조물까지의 높이입니다. **3D 제원 적용**을 누르면 연구선, 화물선, 기타 선박 중 선택한 형태에 치수가 반영됩니다. 업로드에 제원이 없으면 기본 개략 모형으로 재생할 수 있습니다. 제공 선박도 **3D 제원 직접 입력**으로 표시 치수를 조정할 수 있으며 공개 제원은 사이드바에 함께 표시됩니다.

선체와 상부 구조물은 제원에 맞춘 개략 모형입니다. 제원과 선택한 장치 표시 크기는 3D 장면에 적용됩니다. 실측 Roll·Pitch와 가상 파도에서 생성한 Roll·Pitch는 각자의 원래 입력을 사용합니다. 제원을 바꿔도 같은 운동 기록과 PID 이득으로 이어서 재생할 수 있습니다.

3D 화면의 **장치 표시 크기**에서 **실제 크기 (1×)**와 **시연용 확대 (16×)**를 고릅니다. 두 모드의 상판은 각각 0.40 × 0.30 m와 6.40 × 4.80 m로 표시되며 선박을 바꿔도 같은 치수를 사용합니다. 장치 주변을 보려면 카메라를 **수평유지장치 확대**로 바꾸세요.

`pid_model_settings.json`과 성능·설정 JSON의 `vessel`에 표시 제원이 저장됩니다. 사용자 입력 제원이 든 설정 파일을 불러오면 현재 선택한 입력의 3D 제원에 적용합니다. 최적화 체크포인트에는 작업을 시작할 때의 제원이 기록됩니다.

원본 바이트는 수정하지 않습니다. 정제 시각·각도는 별도의 CSV로 다운로드합니다. 파싱에 실패한 시각과 두 자세 중 한쪽이라도 결측 또는 절댓값 상한을 넘는 행을 제외합니다. 중복 시각은 처음 유효한 자세 쌍을 남깁니다. 짧은 공백은 보간하고 허용 간격을 넘는 공백에서는 연속 구간을 나눕니다. 기본 허용 간격은 원본 간격 중앙값의 3.05배입니다. 각 실험은 선택 범위 **안**에 있는 원본 관측점만 사용하여 PCHIP 또는 선형 보간을 합니다. 제어는 기본 0.020초 주기로 계산하며 원본 관측 주파수는 그대로입니다.

Gunnerus의 기본 범위는 원본 시작에서 A 0–60초, B 1,560–1,620초, C 2,850–2,910초입니다. 원본 관측 시각이 범위 경계와 일치하지 않으면 범위 안의 첫 관측점부터 계산하고 마지막 관측점 안에서 제어 스텝을 종료합니다. 학습·검증 구간 사이에 원본 시각이 한 점이라도 겹치면 해당 검증을 비활성화합니다. Gunnerus의 기본 B·C는 같은 실험일의 다른 운항 자세 구간입니다. ACE의 양의 방향은 원본 설정을 확인할 수 있을 때 그에 맞춰 지정해야 하며, 미확인 부호를 선택하면 해당 검증은 그 부호 가정하에서 해석합니다.

실측 모드의 선박 자세 입력은 관측 Roll·Pitch입니다. 3D 수면은 시각화를 위한 별도의 합성 모델입니다. 히브·요와 선형 가속도는 이 계산에서 입력하지 않습니다. 가상 바다 선택을 바꿔도 실측 Roll·Pitch를 사용하는 PID 계산은 그대로입니다.

## 계산 모델

### 회전과 센서

선박 좌표는 `+x` 선수, `+y` 좌현, `+z` 위 방향입니다. `R_ship = Ry(−pitch) Rx(roll)`로 선박을 배치합니다. 짐벌의 외부 Roll 관절은 선박에 고정된 x축을 중심으로 돌고 내부 Pitch 관절은 외부 관절과 함께 움직인 y축을 중심으로 돕니다. 따라서 `R_plate = R_ship Rx(q_roll) Ry(−q_pitch)`로 상판 절대 방향을 구합니다. 엔진과 3D 화면이 같은 변환을 사용합니다. 수평 기준면은 관절 높이에 맞춰 표시하며 세계 좌표계에서 수평입니다.

상판의 모의 IMU는 자세와 자세 변화율에 가우시안 잡음, 고정 자이로 바이어스를 추가합니다. 시간상수를 갖는 상보필터로 기울기를 추정합니다. 한 구간의 세 제어 조건은 같은 센서 잡음 시퀀스와 초기 조건을 사용합니다.

### PID와 짐벌 동역학

각 축 PID의 오차는 상판 목표 0 rad와 추정 자세의 차이입니다. 명령 단위는 N·m입니다. Kp는 N·m/rad, Ki는 N·m/(rad·s), Kd는 N·m·s/rad입니다. 미분은 저역 통과 필터를 거치며, 명령 포화와 기계 한계 밖으로 더 밀어붙일 때 적분이 누적되지 않도록 조건부 적분을 적용합니다.

각 축은 `J (q̈ + α_base) + b q̇ = τ_applied`로 계산합니다. q는 선박 좌표계 기준 관절각(rad), α_base는 선박의 각가속도를 각 관절에 투영한 값(rad/s²), b는 감쇠(N·m·s/rad), τ는 토크(N·m)입니다. J(kg·m²)는 장치 자체 관성에 적재물 질량 × 유효 회전 반경²을 더합니다. 전달 지연, 토크 응답 시간상수, 최대 토크, 상대 회전각과 각속도를 적용합니다. OFF는 관절을 중립 위치에 고정합니다.

기본 가상 모델의 적재물은 1.2 kg이고 Roll/Pitch 관성은 약 0.0432/0.0538 kg·m²입니다. 최대 토크는 1.6/1.8 N·m, 최대 상대 각속도는 각 95°/s, 상대 회전 범위는 각 ±26°입니다. 3D 상판은 0.40 × 0.30 m 기준의 축척을 사용합니다. 균형 잡힌 관절을 가정하며 질량중심 오프셋의 중력 토크, 축 간 관성 결합, 유격, 실제 전원과 IMU 장착 오차는 포함하지 않습니다. 최적 이득은 이 가상 모델과 선택 구간에 대한 결과입니다. 실제 장치에서는 질량·관성·지연 및 제한을 식별한 후 별도 튜닝이 필요합니다.

### 최적화 목적함수

TPE는 가중합 J를 최소화합니다. 표의 항은 모두 무차원입니다.

| 항 | 정규화 | 기본 가중치 |
| --- | --- | ---: |
| Roll RMS | 각도 RMS / 1° | 0.37 |
| Pitch RMS | 각도 RMS / 1° | 0.37 |
| 최대 기울기 | 상판 법선과 수직선 사잇각의 최대 / 5° | 0.08 |
| 모터 사용량 | RMS 토크 / 정격 한계와 RMS 속도 / 속도 한계를 축별 평균 | 0.08 |
| 진동 지표 | 관절 각가속도 RMS / (한계 각속도 ÷ 0.25초)의 축별 평균 | 0.05 |
| 제약 도달 | 토크 포화와 각속도 제한 스텝 비율에 회전각 한계 스텝 비율의 2배를 더한 축별 평균 | 0.20 |

두 RMS에 같은 높은 가중치를 줘 수평유지를 우선합니다. 최대 경사, 구동량, 각가속도를 추가해 RMS가 유사한 조합의 움직임을 비교합니다. 회전각 끝단에는 더 큰 페널티를 주며, 제한 적용 후에도 허용 상태를 벗어났다면 J에 강한 페널티를 부여합니다. 성능 표의 포화 횟수는 연속 포화 구간의 수이고 스텝 수는 그 지속 시간을 확인하기 위한 값입니다.

TPE는 계산 스레드에서 순차 실행하며 완료한 실험을 JSON에 원자적으로 기록합니다. 기본 서버 저장 경로는 시스템 임시 폴더의 `ship-pid-studies`이고 필요하면 `STABILIZER_RUN_DIR`로 바꿀 수 있습니다. 중단을 누르면 현재 실험을 완료한 뒤 멈춥니다. 다시 열려면 체크포인트를 내려받고 동일한 데이터·구간·모델·탐색 설정 및 Optuna 버전에서 불러옵니다. 같은 설정과 시드에서는 이어서 실행한 실험도 동일한 순서로 제안됩니다. 서버 재시작이 잦은 환경에서는 체크포인트 JSON을 별도로 보관합니다.

## 구조와 검증

- `data_loader.py`는 실측 원본을 읽고 분리된 관측 구간을 보간합니다.
- `ship_model.py`, `motor_model.py`, `pid_controller.py`는 자세 운동학과 구동 모델을 정의합니다.
- `simulation.simulate()`는 입력 구간의 시계열과 성능 지표를 반환합니다. Streamlit이나 Plotly를 가져오지 않습니다.
- `optimizer.py`는 반복 실험과 점수 기록을 관리합니다. `evaluation.py`는 지표와 목적함수를 계산합니다.
- `vessel_specs.py`는 선박 제원과 출처를 관리합니다.
- `playback.py`, `visualization.py`는 계산 결과의 재생과 제원에 맞춘 3D 형상을 담당합니다.
- `app.py`와 `ui_*.py`는 한국어 Streamlit 화면과 파일 다운로드를 담당합니다.

python -m pip install -r requirements-dev.txt

## GitHub와 Streamlit Community Cloud

1. GitHub에 새 저장소를 만들고 `app.py`, Python 모듈, `requirements.txt`, `.streamlit/config.toml`, `data/`를 포함한 프로젝트 폴더의 내용을 올립니다.
2. [Streamlit Community Cloud](https://share.streamlit.io/)에서 **Create app**을 선택하고 GitHub의 저장소, 브랜치, 진입 파일 `app.py`를 지정합니다.
3. **Advanced settings**의 Python 버전을 3.11로 지정한 뒤 배포합니다. [공식 배포 안내](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy)

실측 파일의 출처와 이용 조건은 [data/README.md](data/README.md)에 있습니다.
